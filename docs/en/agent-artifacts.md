# Agent Artifacts Directory Structure

This document provides detailed information about the artifacts generated by each agent in AgentDev Suite based on their actual specifications, including file naming conventions, directory structures, and output formats.

## Overview

AgentDev Suite follows a standardized artifact organization system where each agent generates outputs in specific directories with consistent naming conventions. The system supports two contexts:

1. **Feature Development**: When working on specific features, artifacts are organized under `features/{feature-name}/`
2. **Non-Feature Tasks**: For general tasks, artifacts are organized under `docs/agent-outputs/{task-id}/`

## Core Agent Artifacts Structure

### Traditional Development Agents

#### 1. Product Manager (`traditional-pm`)
- **Role Abbreviation**: `pm`
- **File Naming Convention**: `{YYYYMMDD-HHMMSS}-pm-{document-type}.md`

  - Non-feature tasks: `docs/agent-outputs/{task-id}/product-management/`
- **Example Files**:
  - `20250210-103000-pm-prd.md` - Product Requirements Document
  - `20250210-103500-pm-market-analysis.md` - Market analysis report
  - `20250210-104000-pm-roadmap.md` - Product roadmap

#### 4. Developer (`traditional-dev`)
- **Role Abbreviation**: No specific file naming (outputs source code)
- **Primary Outputs**:
  - Source code in `src/` directory
  - Technology-specific test files in `tests/` following technology constraints
- **Documentation Output Directory**:
  - Feature development: `features/{feature-name}/development/`
  - Non-feature tasks: `docs/agent-outputs/{task-id}/development/`
- **Technology-Specific Test Structure**:
  - **Python**: `tests/unit/`, `tests/integration/`, `test_*.py` files, 80%+ coverage
  - **Django**: `tests/`, `<app>/tests.py`, `test_*.py`, 85%+ coverage
  - **Java/Spring Boot**: `src/test/java/` mirroring main structure, `*Test.java`, 70%+ coverage
  - **Node.js/JavaScript**: `tests/`, `__tests__/`, `*.test.js` or `*.spec.js`, 80%+ coverage
  - **TypeScript**: `*.test.ts` or `*.spec.ts`, 80%+ coverage
  - **React**: `__tests__/`, `*.test.jsx`, `ComponentName.test.jsx`, 85%+ coverage
  - **Go**: `*_test.go` alongside source files, 75%+ coverage

## Key Principles

### 1. Consistent Naming Convention
All agent-generated documents follow the pattern: `{YYYYMMDD-HHMMSS}-{role-abbreviation}-{document-type}.md`
- **YYYYMMDD-HHMMSS**: Timestamp for versioning and ordering
- **role-abbreviation**: Unique identifier for each agent role (pm, po, arch, qa, ops, analyst, platform)
- **document-type**: Descriptive name indicating document purpose (prd, user-stories, architecture, test-report, etc.)

### 2. Context-Aware Directory Structure
- **Feature Development**: Artifacts organized under `features/{feature-name}/` for traceability
- **General Tasks**: Artifacts organized under `docs/agent-outputs/{task-id}/` for ad-hoc work
- **Shared Directories**: Some roles share directories (PM/PO, traditional/skill architects, traditional/skill QA)

### 3. Technology-Specific Constraints
- **Development Tests**: Follow language/framework-specific test structure and coverage requirements
- **QA Automation**: Organized by testing domain (e2e, performance, security) with tool-specific subdirectories
- **Skill Projects**: Follow progressive disclosure structure with platform configurations

### 4. Collaboration and Traceability
- **Input/Output Mapping**: Each agent reads from and writes to specific directories
- **Phase Progression**: Artifacts flow through development phases with clear handoffs
- **Cross-role Coordination**: Shared directories facilitate collaboration between related roles
